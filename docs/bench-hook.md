# ベンチ結果の受け取り

`bench` のフックはベンチを回し、結果を次の形で `$ISUTORI_BENCH_RESULT` に書きます。0 以外で終了したときや、結果を書かずに終了したときは、ベンチの fail ではなくエラー (終了コード 1) になります。

```json
{"passed": true, "score": 12345, "message": "ポータルに表示された内容など"}
```

`bench` には、ポータルに合わせて次のどれかを書きます。

- `isutori receive`: `http://127.0.0.1:7878/` で待ち受けます。ポータルで Enqueue し、終わったら結果をこのページのフォームに入力してください
- `isutori autobench <ポータルの URL> <対象サーバー>`: ポータルをブラウザで開き、ユーザースクリプトに Enqueue させて結果を受け取ります。待っている間も、上と同じフォームから手動で入力できます
- 自作のスクリプト: ポータルにベンチを回す API などがあれば、それを呼んで結果を書きます

`autobench` の対象サーバーは、ポータルの選択肢にある番号か IP で書きます。最後に選んだサーバーが最終計測にも使われるポータルがあるため、ユーザースクリプトは一致する選択肢が無いとき、別のサーバーで代用せず、エラーを返します。

`autobench` がブラウザを開くコマンドは `--open-command` で指定できます。未指定なら、`wslview`、`xdg-open`、`open` のうち最初に見つかったものを使います。`autobench` で使うユーザースクリプトを用意する方法は [ユーザースクリプト](userscript.md) にあります。

`receive` と `autobench` は結果をファイルに保存してから送信元へ受領の成功を返します。保存に失敗した場合はエラーを返し、再送を受け付けます。自作の bench フックも結果の保存を終えてから成功として終了してください。

## API でベンチを回す

API の利用が許可されていれば、競技リポジトリに登録・結果取得のコマンドを用意し、`hooks.bench` を差し替えられます。例えば `ops/bench-api.sh` を用意した場合は、次のように設定します。キューやほかのフックを変更する必要はありません。

```toml
[hooks]
bench = "ops/bench-api.sh"
```

導入前に、API によるベンチの登録と結果取得の可否、使える認証方法、結果を問い合わせてよい間隔を確認してください。当日マニュアルなどで分からない点は運営へ問い合わせます。許可が不明な間も、認められたブラウザ操作や手動入力で導入を進められます。

API 用コマンドは次の点を守ってください。

- 指定した対象で登録し、そのジョブの確定結果を `$ISUTORI_BENCH_RESULT` へ上記の JSON 形式で保存する。最新のジョブや途中スコアで代用しない。
- ベンチ自体が不合格でも、結果を正常に取得・保存できたら `passed: false` として終了コード 0 を返す。登録や結果取得、保存の失敗は 0 以外で終了する。
- 登録要求がタイムアウトしても、未登録とは決めつけて再送しない。既存ジョブの有無を確認し、成否が分からなければエラーとして知らせる。

資格情報は手元の認証ファイルや環境変数などから渡し、リポジトリ、ログ、エージェントへの入力に含めないでください。認証方法、ジョブの識別、結果の確定条件はポータルごとに実装します。
